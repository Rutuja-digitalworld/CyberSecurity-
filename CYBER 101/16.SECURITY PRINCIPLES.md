# 🔐 Security Principles 

# TASK 1: CIA Security Triad

The **CIA Triad** is the foundation of information security. It consists of:

<img width="778" height="695" alt="image" src="https://github.com/user-attachments/assets/f14f9b13-77de-4bff-a7e4-6f894b18069c" />


| Principle              | Meaning                                                                              | Example                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 🔒 **Confidentiality** | Only authorized people can access information.                                       | Credit card details should only be accessible to the payment processor.              |
| 🛡️ **Integrity**      | Data should not be modified without authorization, and changes should be detectable. | An online order's shipping address should not be changed by an attacker.             |
| ⚡ **Availability**     | Systems and data should be available when required.                                  | An online shopping website should be accessible when customers want to place orders. |

----------------------
### 🔒 Confidentiality

* Prevents **unauthorized access or disclosure** of information.
* Protects sensitive information such as:

  * Passwords
  * Credit card details
  * Medical records
  * Personal information

**Example:** A healthcare provider must protect a patient's medical records from unauthorized people.

----------------------

### 🛡️ Integrity

* Ensures that data remains **accurate and unchanged** unless an authorized modification is made.
* Unauthorized modification should also be **detectable**.

**Example:** If an attacker changes the shipping address of an online order, the package may be delivered to the wrong person.

-------------------------------

### ⚡ Availability

* Ensures that systems, services, and information are **accessible when needed**.

**Example:** If an online shopping website is down, customers cannot browse products or place orders.

> **Note:** All three CIA principles do not always have equal importance.
> For example, a university announcement may not need confidentiality, but its **integrity is very important**.

---

## 2. CIA in Different Systems

### 🛒 Online Shopping

**Confidentiality:**
Customer payment and personal information should not be disclosed to unauthorized parties.

**Integrity:**
Order details such as quantity, price, and shipping address should not be modified illegally.

**Availability:**
The website/app should remain available so customers can browse and place orders.

### 🏥 Healthcare System

**Confidentiality:**
Patient medical records must be protected from unauthorized disclosure.

**Integrity:**
Incorrectly modified medical records can result in incorrect treatment.

**Availability:**
Doctors need access to patient records when treating patients.

---

# 3. Beyond CIA

Security also includes **Authenticity** and **Nonrepudiation**.

### ✅ Authenticity

**Authenticity** ensures that the data, file, message, or request is actually from the **claimed source**.

**Example:**
A company receiving an order for **1000 cars** needs to verify that the order was genuinely placed by the claimed customer.

--------------------

### ✍️ Nonrepudiation

**Nonrepudiation** ensures that the original sender **cannot later deny** having created or sent the data.

**Example:**
If a customer places an order for 1000 cars, the company should have evidence proving that the customer actually placed the order.

### 🔗 Difference

| Concept            | Main Question                              |
| ------------------ | ------------------------------------------ |
| **Authenticity**   | "Is this really from the claimed source?"  |
| **Nonrepudiation** | "Can the source deny sending/creating it?" |

---

## 4. Parkerian Hexad

The **Parkerian Hexad**, proposed by **Donn Parker in 1998**, extends security into **six elements**.

### 🔷 Six Elements

1. **Availability**
2. **Utility**
3. **Integrity**
4. **Authenticity**
5. **Confidentiality**
6. **Possession**

### 📌 Utility

**Utility** means that information must be in a **useful and usable form**.

**Example:**
A laptop contains encrypted data, but the owner has lost the decryption key.

* Data is still present ✅
* Laptop is available ✅
* But the information cannot be used ❌

Therefore, the information has **no utility** to the user.

### 📦 Possession

**Possession** means protecting information from **unauthorized taking, copying, or control**.

**Example 1:**
An attacker steals a backup drive containing important data.

**Example 2:**
Ransomware encrypts an organization's files and prevents the organization from controlling/accessing them.

In both cases, the organization can lose **possession/control of its information**.

# TASK 2:🔐 DAD Triad 
<img width="718" height="636" alt="image" src="https://github.com/user-attachments/assets/87eb9f82-c291-450b-ad53-5358ed4b625d" />

The **DAD Triad** represents attacks against the three principles of the **CIA Triad**.

| CIA Principle       | Opposite Attack          | Meaning                                 |
| ------------------- | ------------------------ | --------------------------------------- |
| **Confidentiality** | **Disclosure**           | Unauthorized access or exposure of data |
| **Integrity**       | **Alteration**           | Unauthorized modification of data       |
| **Availability**    | **Destruction / Denial** | Making data or systems unavailable      |

### 🔓 Disclosure

**Disclosure** is an attack against **Confidentiality**.

* Occurs when confidential or private information is accessed or exposed by an unauthorized person.
* The attacker may steal data and make it publicly available.

**Example:**
An attacker gains access to customer records and **dumps them online**.

➡️ **Attack: Disclosure**

---

### ✏️ Alteration

**Alteration** is an attack against **Integrity**.

* Occurs when data is **modified without authorization**.
* The altered information may cause incorrect decisions or actions.

**Example:**
An attacker modifies a patient's medical record, causing a doctor to provide the wrong treatment.

➡️ **Attack: Alteration**

---

### 💥 Destruction / Denial

**Destruction/Denial** is an attack against **Availability**.

* Occurs when data, systems, or services are **destroyed or made unavailable**.
* It prevents legitimate users from accessing the required resources.

**Example:**
Attackers switch off both the main and backup power supplies, causing the entire network to shut down.

➡️ **Attack: Denial**

---

## 2. DAD Triad and Patient Records

### Disclosure

If an attacker steals patient records and publishes them online, the healthcare provider suffers a **confidentiality breach**.

### Alteration

If an attacker modifies patient records, doctors may provide incorrect treatment. This attacks **integrity** and can potentially be life-threatening.

### Destruction / Denial

If attackers make the medical database unavailable, doctors cannot access patient records and the facility may be unable to operate properly.

---

## 3. Balance Between CIA Principles

Security requires a **balance between Confidentiality, Integrity, and Availability**.

* Excessive **Confidentiality and Integrity** controls can make information difficult to access, reducing **Availability**.
* Increasing **Availability** too much can sometimes weaken **Confidentiality and Integrity**.
* Therefore, security controls should be designed to maintain an appropriate balance between all three principles.

--------------------

### Answers

**Q1.** The attacker managed to gain access to customer records and dumped them online. What is this attack?
**Answer:** **Disclosure**

**Q2.** A group of attackers were able to locate both the main and the backup power supply systems and switch them off. As a result, the whole network was shut down. What is this attack?
**Answer:** **Denial**

# <u> TASK3: FUNDAMENTALS OF SECURITY MODELS </u>
Security models are used to **design and implement systems that provide specific security properties**, such as confidentiality or integrity.

The three foundational security models are:

1. **Bell-LaPadula Model**
2. **Biba Integrity Model**
3. **Clark-Wilson Model**

---

# 1. Bell-LaPadula Model

The **Bell-LaPadula (BLP) Model** is designed to protect **Confidentiality**.

It controls how subjects at different security levels can **read and write information**.

### 🔹 Simple Security Property

Also called **“No Read Up.”**

> A subject at a lower security level **cannot read** an object at a higher security level.

**Purpose:** Prevents unauthorized access to highly sensitive information.

**Example:**
A user with **Secret** clearance cannot read a **Top Secret** file.

---

### 🔹 Star Security Property (*-Property)

Also called **“No Write Down.”**

> A subject at a higher security level **cannot write** information to an object at a lower security level.

**Purpose:** Prevents sensitive information from being leaked to a lower security level.

**Example:**
A Top Secret user cannot copy Top Secret information into a Public file.

---

### 🔹 Discretionary Security Property

This property uses an **access matrix** to control read and write permissions.

Example:

| Subject   | Object A   | Object B  |
| --------- | ---------- | --------- |
| Subject 1 | Write      | No Access |
| Subject 2 | Read/Write | Read      |

---

### 📌 Bell-LaPadula Summary

The first two properties can be remembered as:

> **“Write Up, Read Down”**

* **Read Down** → Read information from a lower security level.
* **Write Up** → Write information to a higher security level.
* ❌ No Read Up
* ❌ No Write Down

**Main Goal → Confidentiality**

### Limitation

Bell-LaPadula was **not designed to handle file-sharing** effectively.

---

# 2. Biba Integrity Model

The **Biba Model** is designed to protect **Integrity**.

It is essentially opposite to Bell-LaPadula's information-flow rules.

### 🔹 Simple Integrity Property

Also called **“No Read Down.”**

> A subject at a higher integrity level **cannot read** an object at a lower integrity level.

**Example:**
A high-integrity process should not read potentially untrusted low-integrity data.

---

### 🔹 Star Integrity Property

Also called **“No Write Up.”**

> A subject at a lower integrity level **cannot write** to an object at a higher integrity level.

**Purpose:** Prevents low-integrity data from contaminating high-integrity data.

**Example:**
A low-integrity user cannot modify a high-integrity database.

---

### 📌 Biba Summary

The two main properties can be remembered as:

> **“Read Up, Write Down”**

* **Read Up** → Read from a higher integrity level.
* **Write Down** → Write to a lower integrity level.
* ❌ No Read Down
* ❌ No Write Up

**Main Goal → Integrity**

### Limitation

The Biba Model has limitations in dealing with **internal/insider threats**.

---

# 3. Clark-Wilson Model

The **Clark-Wilson Model** also focuses on **Integrity**.

Instead of mainly controlling information flow through security levels, it uses **well-defined procedures and verification mechanisms** to maintain data integrity.

It has four important concepts:

### 🔹 1. Constrained Data Item (CDI)

A **CDI** is data whose **integrity needs to be protected**.

**Example:**
A bank account balance.

---

### 🔹 2. Unconstrained Data Item (UDI)

A **UDI** is data that is outside the controlled integrity system.

It can include **user input and system input**.

**Example:**
A value entered by a user into a banking application.

---

### 🔹 3. Transformation Procedures (TPs)

**TPs** are programmed operations that modify or access CDIs while maintaining their integrity.

Examples:

* Read
* Write
* Transfer money
* Update account balance

The procedures must ensure that the CDI remains valid.

---

### 🔹 4. Integrity Verification Procedures (IVPs)

**IVPs** check whether the **CDIs are valid and maintain their required integrity**.

**Example:**
A banking system checks whether account balances satisfy its integrity rules.

---

# 📊 Comparison of Security Models

| Model             | Main Goal       | Important Rules / Concepts |
| ----------------- | --------------- | -------------------------- |
| **Bell-LaPadula** | Confidentiality | No Read Up, No Write Down  |
| **Biba**          | Integrity       | No Read Down, No Write Up  |
| **Clark-Wilson**  | Integrity       | CDI, UDI, TP, IVP          |

---

# 🔄 Bell-LaPadula vs Biba

| Bell-LaPadula                  | Biba                     |
| ------------------------------ | ------------------------ |
| Focuses on **Confidentiality** | Focuses on **Integrity** |
| **No Read Up**                 | **No Read Down**         |
| **No Write Down**              | **No Write Up**          |
| Write Up, Read Down            | Read Up, Write Down      |

---

# 📚 Other Security Models

Other security models include:

* **Brewer and Nash Model**
* **Goguen-Meseguer Model**
* **Sutherland Model**
* **Graham-Denning Model**
* **Harrison-Ruzzo-Ullman Model**

---

# TASK 4:🛡️ Defence-in-Depth

## 1. Definition

**Defence-in-Depth** is a security strategy that uses **multiple layers of security controls** to protect a system.

It is also known as **Multi-Level Security**.

The main idea is:

> **Do not depend on a single security control. Use multiple layers of protection.**

If one security layer fails, the other layers can still provide protection.

---

## 2. Example

Suppose you keep important documents and expensive items in a drawer.

Instead of relying only on the drawer lock, you can use multiple security layers:

```text
Important Items
      ↓
🔒 Locked Drawer
      ↓
🚪 Locked Room
      ↓
🔐 Locked Apartment Door
      ↓
🚧 Locked Building Gate
      ↓
📹 Security Cameras
```

Each layer provides additional protection.

If a thief manages to bypass one layer, they still have to overcome the remaining layers.

---

## 3. Purpose of Defence-in-Depth

Defence-in-Depth is used to:

* Reduce the chance of successful attacks.
* Provide **multiple layers of protection**.
* Slow down attackers.
* Limit the damage if one security control fails.
* Protect important systems and information from different types of threats.

---

## 4. Important Point

Defence-in-Depth **cannot guarantee that every attack will be stopped**.

Its purpose is to make an attack **more difficult, time-consuming, and less likely to succeed** by using multiple security controls.

# 🔐 TASK 5: ISO/IEC 19249 — Security Principles

**ISO/IEC 19249:2017** provides architectural and design principles for creating secure products, systems, and applications.

It contains **5 architectural principles** and **5 design principles**.

The International Organization for Standardization (ISO) and the International Electrotechnical Commission (IEC) have created the ISO/IEC 19249.

---

# 5 ARCHITECTURAL PRINCIPLES OF ISO/IEC 19249 

### 1. Domain Separation

Groups related components into separate domains with their own security attributes.

**Example:**
Operating system kernel runs in **Ring 0**, while user applications run in **Ring 3**.

---

### 2. Layering

Structures a system into multiple layers, allowing security policies to be applied at different levels.

**Example:**
The **OSI model** has seven layers.

Layering is also related to **Defence-in-Depth**.

---

### 3. Encapsulation

Hides internal implementation and prevents direct manipulation of data.

**Example:**
An object provides an `increment()` method instead of allowing direct access to its `seconds` variable.

---

### 4. Redundancy

Uses additional components to improve **availability and integrity**.

**Examples:**

* Two power supplies in a server.
* RAID 5.
* Backup systems.

If one component fails, another can continue providing the service.

---

### 5. Virtualization

Shares physical hardware between multiple operating systems using virtual environments.

It provides **sandboxing and security boundaries**.

**Example:**
Running a suspicious program inside a virtual machine to isolate it from the main system.

------------------
# 5 DESIGN PRINCIPLES OF ISO/IEC 19249 
## 🔐 ISO/IEC 19249 — Design Principles

| No.   | Design Principle                               | Meaning                                                                           | Example                                                                   |
| ----- | ---------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **1** | **Least Privilege**                            | Give users/processes only the minimum permissions required to perform their task. | A sales representative gets access only to product and price information. |
| **2** | **Attack Surface Minimisation**                | Reduce the number of possible points that attackers can exploit.                  | Turn off an unnecessary or insecure server/service.                       |
| **3** | **Centralized Parameter Validation**           | Validate system/user inputs centrally to prevent malicious or invalid input.      | A central library checks user input before processing it.                 |
| **4** | **Centralized General Security Services**      | Centralize common security services such as authentication and authorization.     | Using a centralized authentication server.                                |
| **5** | **Preparing for Error and Exception Handling** | Design systems to handle errors and unexpected situations safely.                 | ATM software handles network failure and power failure safely.            |

# 📝 Questions & Answers

### Q1. Which principle are you applying when you turn off an insecure server that is not critical to the business?

**Answer: 2 — Attack Surface Minimisation**

Turning off an unnecessary/insecure server reduces the number of possible attack points.

---

### Q2. Your company hired a new sales representative. Which principle are they applying when they tell you to give them access only to the company products and prices?

**Answer: 1 — Least Privilege**

The employee receives **only the permissions required** for their job.

---

### Q3. While reading the code of an ATM, you noticed a huge chunk of code to handle unexpected situations such as network disconnection and power failure. Which principle are they applying?

**Answer: 5 — Preparing for Error and Exception Handling**

The system is designed to properly handle unexpected failures and exceptions.

# TASK 6:🔐 Trust Principles (ZERO TRUST VS TRUST BUT VERIFY)

Trust is an important part of security because users and systems need to interact with each other. However, excessive or uncontrolled trust can create security risks.

Two important security principles related to trust are:

1. **Trust but Verify**
2. **Zero Trust**

---

## 1. Trust but Verify

**Trust but Verify** means that even when we trust an entity, we should **still verify its actions and behaviour**.

The entity can be:

* A user
* A computer
* A system
* A service

### How it works

Verification is usually performed through:

* **Logging**
* **Monitoring**
* **Security analysis**
* **Proxy systems**
* **Intrusion Detection Systems (IDS)**
* **Intrusion Prevention Systems (IPS)**

For example, an organization may trust an employee but still monitor system logs to detect unusual activity.

### Important Point

It is not practical for humans to manually verify every action performed by every user. Therefore, **automated security mechanisms** are required.

---

# 2. Zero Trust

**Zero Trust** treats **trust itself as a security vulnerability**.

Its basic idea is:

> **“Never trust, always verify.”**

Under Zero Trust:

* Every entity is considered **potentially untrusted**.
* Trust is not automatically given based on:

  * Network location
  * Device ownership
  * Being inside an organization's network
* **Authentication and authorization** are required before accessing resources.
* Access should be continuously controlled and verified.

### Example

In an older security model:

```text
Internet → Firewall → Internal Network → Trusted Users
```

Once someone gets inside the internal network, they may receive more trust.

In Zero Trust:

```text
User/Device
     ↓
Authentication
     ↓
Authorization
     ↓
Resource Access
     ↓
Continuous Verification
```

Being inside the company's network **does not automatically make a user trusted**.

---

# 3. Zero Trust and Insider Threats

Zero Trust is particularly useful for reducing the impact of **insider-related threats**.

If an attacker compromises an employee's account, Zero Trust can limit what that account can access because each resource requires appropriate authentication and authorization.

Therefore, even if one account is compromised, the attacker's access can be **more contained**.

---

# 4. Microsegmentation

**Microsegmentation** is one implementation of Zero Trust.

It divides a network into **very small segments**, potentially as small as a **single host**.

Communication between segments can require:

* Authentication
* Access control checks
* Authorization
* Other security controls

---

# 5. Trust but Verify vs Zero Trust

| **Trust but Verify**                    | **Zero Trust**                                           |
| --------------------------------------- | -------------------------------------------------------- |
| Trust exists, but actions are verified. | Trust is not automatically granted.                      |
| Focuses on monitoring trusted entities. | Treats every entity as potentially untrusted.            |
| Uses logging and monitoring.            | Requires authentication and authorization before access. |
| Trust is present but monitored.         | **“Never trust, always verify.”**                        |
| Helps detect abnormal behaviour.        | Helps limit unauthorized access and contain breaches.    |

### ⚠️ Important Point

Zero Trust cannot always be applied to an extreme level because excessive verification and access controls can negatively affect **business usability and operations**.

The goal is to apply Zero Trust **where it is feasible and appropriate**, while maintaining practical business operations.

# TASK 7:🔐Threat VS Risk

These three terms are closely related in cybersecurity, but they have **different meanings**.

## 1. Vulnerability

A **vulnerability** is a **weakness** in a system that can potentially be exploited or cause damage.

**Example:**
A showroom has doors and windows made of standard glass. The glass is a **weakness** because it can be broken.

**Cybersecurity example:**
A database software has an unpatched security flaw.

---

## 2. Threat

A **threat** is a **potential danger** that can take advantage of a vulnerability.

**Example:**
Someone breaking the showroom's glass doors or windows is a **threat**.

**Cybersecurity example:**
An attacker using a known exploit against a vulnerable database is a **threat**.

---

## 3. Risk

**Risk** is concerned with the **likelihood that a threat will exploit a vulnerability and the resulting impact** on the organization.

In simple terms:

> **Risk = Likelihood of exploitation + Potential impact**

**Example:**
If there is a high chance that someone will break the showroom's glass and this could cause significant financial loss, the showroom has a **high risk**.

---

### 🏥 Cybersecurity Example

A hospital uses a database to store patient medical records.

* **Vulnerability:** The database contains a known security flaw.
* **Threat:** An attacker can exploit that flaw.
* **Risk:** The attacker may gain access to medical records, causing financial, legal, and operational impact.

If a **working proof-of-concept exploit** has been publicly released, it indicates that the threat is more concrete and the organization should assess the resulting risk and take appropriate action.

| Term              | Simple Meaning      | Example                                   |
| ----------------- | ------------------- | ----------------------------------------- |
| **Vulnerability** | Weakness            | Unpatched database                        |
| **Threat**        | Potential danger    | Attacker with an exploit                  |
| **Risk**          | Likelihood + impact | Possible data breach and its consequences |
