# 🔐 Security Misconfigurations

## 📌 What It Is

Security misconfigurations happen when systems, servers, or applications are deployed with unsafe defaults, incomplete settings, or exposed services.

These are usually **configuration mistakes rather than coding bugs**. They can create easy entry points for attackers.

---

## ⚠️ Why It Matters

A small configuration mistake can:

- Expose sensitive information
- Allow unauthorised access
- Enable privilege escalation
- Expose internal services
- Give attackers a foothold into the system

Modern applications use cloud platforms, APIs, containers, third-party services, and complex infrastructure. Therefore, one incorrectly configured component can affect the security of the entire application.

---

## 💥 Example

In 2017, Uber suffered a data breach after attackers obtained access to credentials stored in a private GitHub repository. The attackers then accessed an AWS environment and obtained sensitive information.

This demonstrates how poor security practices and exposed credentials can lead to a major security incident.

---

## 🔎 Common Patterns

### 1. Default Credentials
Default usernames and passwords are left unchanged.

### 2. Exposed Services
Unnecessary services, ports, or administrative interfaces are accessible from the internet.

### 3. Cloud Misconfiguration
Cloud storage or permissions are incorrectly configured.

Examples:

```text
AWS S3
Azure Blob Storage
Google Cloud Storage
````

### 4. Missing Authentication

APIs or endpoints can be accessed without proper authentication or authorisation.

### 5. Verbose Error Messages

Applications expose:

```text
Stack traces
File paths
Database information
Framework versions
Internal system details
```

### 6. Outdated Software

Old frameworks, libraries, containers, or operating systems may contain known vulnerabilities.

### 7. Exposed AI/ML Services

AI or ML endpoints may be accessible without appropriate authentication and access controls.

---

## 🛡️ How To Prevent It

* Change all default credentials
* Remove unnecessary services and features
* Apply the principle of least privilege
* Restrict unnecessary network exposure
* Keep software and dependencies patched
* Disable debug mode in production
* Hide detailed stack traces from users
* Regularly audit cloud permissions
* Secure APIs with authentication and authorisation
* Monitor exposed services and endpoints
* Include configuration security checks in CI/CD pipelines
