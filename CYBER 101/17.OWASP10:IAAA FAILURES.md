# TASK 1: OWASP & OWASP Top 10

## 1. What is OWASP?

**OWASP = Open Worldwide Application Security Project**

OWASP is a **non-profit organization/community** that works to improve the security of software and web applications.

It provides:

* Security guidelines
* Security testing resources
* Documentation
* Tools
* Best practices
* The **OWASP Top 10**

### Simple meaning:

> OWASP helps developers and security professionals understand and prevent common security vulnerabilities in applications.

---

# 2. What is OWASP Top 10?

**OWASP Top 10** is a list of the **10 most important/common categories of web application security risks** identified by OWASP.

It is mainly used by:

* Web developers
* Cybersecurity professionals
* Penetration testers
* Security learners

It helps answer:

> **"What are the major security problems that can exist in a web application?"**

---

# 3. What does `A01`, `A02` etc. mean?

This is important:

`A01`, `A02`, `A03`... are **category identifiers**, not a separate full form.

### Format:

```text
A + Number
```

* **A** → stands for **Application**
* **01** → category number/ranking identifier

So:

**A01 = Application category 01**

---

# TASK2:# 🔐 IAAA — Identity, Authentication, Authorisation & Accountability

**IAAA** is a simple way to understand how applications identify users, verify them, control their permissions, and track their actions.

> **Identity → Authentication → Authorisation → Accountability**

These four stages are connected. **You cannot properly move to the next stage if the previous stage has not been established.**

---

## 🧩 The 4 Components of IAAA

| Stage                 | Meaning                                                   | Simple Question             | Example                   |
| --------------------- | --------------------------------------------------------- | --------------------------- | ------------------------- |
| 🪪 **Identity**       | The unique account representing a person/service          | **Who are you?**            | User ID, Email            |
| 🔑 **Authentication** | Proving that the claimed identity is genuine              | **Can you prove it?**       | Password, OTP, Passkey    |
| 🛡️ **Authorisation** | Defining what the authenticated identity is allowed to do | **What can you access/do?** | User vs Admin permissions |
| 📋 **Accountability** | Recording and alerting on user activities                 | **Who did what and when?**  | Login logs, alerts        |

---

## 1️⃣ Identity 🪪

**Identity** represents a unique person or service in an application.

### Examples:

* User ID
* Email address
* Username
* Service account

```text
Rutuja → rutuja@example.com
```

The application first needs to know **which account/identity is involved**.

---

## 2️⃣ Authentication 🔑

**Authentication** is the process of proving that the claimed identity actually belongs to the user.

### Common methods:

* 🔐 Password
* 📱 OTP
* 🔑 Passkeys
* 👆 Biometrics

### Example:

```text
Identity:
rutuja@example.com

        ↓

Authentication:
Password / OTP / Passkey

        ↓

Identity verified ✅
```

**Question answered:**

> "Are you really the person associated with this identity?"

---

## 3️⃣ Authorisation 🛡️

**Authorisation** determines what an authenticated user is **allowed to access or perform**.

### Example:

```text
Normal User
   ↓
View own profile
Edit own profile

Admin
   ↓
View all users
Delete users
Manage accounts
```

Even if two users are successfully authenticated, **they may have different permissions**.

### Remember:

> **Authentication = Who are you?**
> **Authorisation = What are you allowed to do?**

---

## 4️⃣ Accountability 📋

**Accountability** means recording and monitoring user actions so that activity can be traced back to an identity.

It answers:

> **Who did what, when, and from where?**

### Examples of events that can be logged:

```text
✅ Login attempt
❌ Failed login
🔑 Password change
👤 Account modification
📁 File access
⚙️ Privilege change
```

Security alerts can then be generated for suspicious activity.

---

# ⚠️ Why IAAA Matters in Cybersecurity

The **OWASP Top 10:2025** categories covered in this room are related to failures in implementing IAAA correctly.

Weaknesses in these areas can allow attackers to:

* 🔓 Access another user's data
* 🚨 Bypass security controls
* ⬆️ Gain unauthorised privileges
* 👤 Act as another user
* 🕵️ Perform actions without proper detection

### The 3 OWASP categories covered:

| OWASP Category                        | IAAA Area         |
| ------------------------------------- | ----------------- |
| **A01 — Broken Access Control**       | 🛡️ Authorisation |
| **A07 — Authentication Failures**     | 🔑 Authentication |
| **A09 — Logging & Alerting Failures** | 📋 Accountability |
