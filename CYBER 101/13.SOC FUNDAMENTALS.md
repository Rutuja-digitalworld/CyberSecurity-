# 🛡️TASK1: Security Operations Center (SOC)

## 🔐 Why is Security Important?

Technology has made our lives more efficient, but it also brings **more responsibility**.

Nowadays, important data or **secrets** are stored in:

* Networks
* Computer systems
* Digital applications

If an unauthorized person **disrupts, modifies, or steals** this data, it can cause serious damage to an organization.

### ⚠️ Cybersecurity Threats

Threat actors continuously discover and exploit **new vulnerabilities** in networks and systems.

Traditional security methods may not always be enough to protect against these threats.

---

# 🏢 What is a SOC?

**SOC = Security Operations Center**

A SOC is a **dedicated facility operated by a specialized security team**.

The main purpose of a SOC is to:

* 👀 Continuously monitor the organization's **network and resources**
* 🔍 Identify **suspicious activities**
* 🛡️ Prevent or reduce damage from security threats

---

# ⏰ SOC Working

A SOC generally works:

```text

```

### 🧠 In Simple Words

> **A SOC is a security team that continuously monitors an organization's systems and network to detect suspicious activities and protect against cyber threats.**

# 🔍 Detection

Detection means **finding security problems, suspicious activities, and attacks**.

The SOC mainly focuses on four types of detection:

### 1. Detect Vulnerabilities

**Vulnerability = A weakness that an attacker can exploit.**

* Vulnerabilities can exist in software such as:

  * Operating Systems
  * Programs
  * Servers
  * Computers
* Example: The SOC may find Windows computers that need to be patched against a known vulnerability.
* Vulnerabilities are not always directly the SOC's responsibility.
* However, **unfixed vulnerabilities reduce the security of the entire company.**

---

### 2. Detect Unauthorized Activity

**Unauthorized activity = Activity performed without proper permission.**

Example:

* An attacker discovers an employee's username and password.
* The attacker uses them to log in to the company's system.
* The SOC must detect this activity quickly before damage occurs.

**Clues such as geographic location can help detect unauthorized activity.**

---

### 3. Detect Policy Violations

**Security Policy = A set of rules and procedures created to protect a company from security threats and ensure compliance.**

A **policy violation** happens when someone breaks these security rules.

Examples:

* Downloading pirated media files.
* Sending confidential company files insecurely.

> What is considered a violation can vary from one company to another.

---

### 4. Detect Intrusions

**Intrusion = Unauthorized access to systems or networks.**

Examples:

* An attacker successfully exploits a web application.
* A user visits a malicious website and their computer becomes infected.

---

# 🚨 Response

### Support with Incident Response

Once a security incident is detected, certain steps are taken to respond to it.

The response includes:

1. **Minimizing the impact** of the incident.
2. Performing **Root Cause Analysis (RCA)**.

**RCA = Root Cause Analysis**

**What is RCA?**
It means finding the **actual reason why the incident happened**.

The SOC team also helps the **Incident Response Team** carry out these steps.

---

# 🏛️ 3 Pillars of SOC

A mature SOC is based on three main pillars:

### 1. 👥 People

Professional security individuals who work in the SOC.

### 2. ⚙️ Process

Proper rules, procedures, and methods used by the SOC team.

### 3. 💻 Technology

Modern security tools and solutions used for monitoring and security operations.

---

## 🔗 How the 3 Pillars Work Together

**People + Process + Technology = Mature SOC**

These three pillars **coexist in a SOC environment**.

A team of professional people, using advanced security tools and following proper processes, creates a **mature SOC environment** that can efficiently detect and respond to different security incidents.

# TASK 3: PEOPLE
# 👥 People in a SOC

Even though many security tasks are becoming automated, **People are still very important in a SOC**.

Security solutions can generate many alerts. This can create **noise**, making it difficult to identify which alerts are actually harmful.

### 🚒 Simple Example

Imagine a fire brigade receives many fire alarms at the same time.

When they reach the locations, they discover that most alarms were caused by **cooking smoke**, not actual fires.

➡️ This wastes **time and resources**.

Similarly, in a SOC, human professionals help security solutions identify **truly harmful activities** and respond quickly.

---

# 🏢 SOC Team Roles

The **People** in a SOC are known as the **SOC Team**.

## 1. 🟢 SOC Analyst — Level 1

**Role:** First responder

* All alerts generated by security solutions are first checked by Level 1 Analysts.
* They perform **basic alert triage**.
* They determine whether an alert is **harmful or not**.
* They report the detection through the proper channels.

> 💡 **Alert Triage = Quickly checking and classifying an alert to determine its importance.**

---

## 2. 🟡 SOC Analyst — Level 2

**Role:** Deeper investigation

* Some alerts require more detailed investigation.
* Level 2 Analysts investigate these alerts further.
* They **correlate data from multiple sources**.
* They perform a proper analysis of the detection.

> 💡 **Correlate Data = Compare information from different sources to understand an incident better.**

---

## 3. 🔴 SOC Analyst — Level 3

**Role:** Experienced threat investigation

* Level 3 Analysts are experienced security professionals.
* They **proactively search for threat indicators**.
* They support **incident response activities**.
* Critical detections reported by Level 1 and Level 2 may require:

  * **Containment**
  * **Eradication**
  * **Recovery**

Their experience is especially useful during serious security incidents.

---

## 4. ⚙️ Security Engineer

**Role:** Deploy and configure security solutions

* SOC Analysts work with different security solutions.
* These solutions need to be **deployed and configured**.
* Security Engineers deploy and configure them.
* They ensure the solutions operate smoothly.

---

## 5. 🧠 Detection Engineer

**Role:** Create security detection rules

**Security Rules = Logic built into security solutions to detect harmful activities.**

* Level 2 and Level 3 Analysts often create these rules.
* Some SOC teams have a dedicated **Detection Engineer** for this responsibility.
* Their main focus is establishing rules that help security solutions detect threats.

---

## 6. 👨‍💼 SOC Manager

**Role:** Manage the SOC team and its processes

* Manages the processes followed by the SOC team.
* Provides support to the team.
* Communicates with the **CISO (Chief Information Security Officer)**.
* Provides updates about:

  * Current security posture
  * SOC team's efforts

# 🛡️TASK 4: Processes

SOC team ke different roles ke saath different **processes** bhi hote hain. These processes help the SOC team **detect, investigate, report, and respond** to security threats.

---

## 🚨 1. Alert Triage
<img width="811" height="657" alt="image (57)" src="https://github.com/user-attachments/assets/95574220-39a4-4340-87ea-f6809572669a" />

**Alert Triage** is the **basis of the SOC team**.

### What is Alert Triage?

Alert triage is the **first response to any security alert**.

It focuses on:

* Analyzing the specific alert
* Determining the **severity** of the alert
* Prioritizing the alert
* Understanding whether the alert is harmful or not

### 🎯 The 5 Ws of Alert Triage

The SOC analyst tries to answer these **5 questions**:

| 5 W        | Meaning              |
| ---------- | -------------------- |
| **What?**  | What happened?       |
| **When?**  | When did it happen?  |
| **Where?** | Where did it happen? |
| **Who?**   | Who was involved?    |
| **Why?**   | Why did it happen?   |

### 📌 Example

**Alert:** Malware detected on Host: **GEORGE PC**

| 5 W        | Answer                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------- |
| **What?**  | A malicious file was detected on a host inside the organization's network.                                      |
| **When?**  | The file was detected at **13:20 on June 5, 2024**.                                                             |
| **Where?** | The file was detected on **GEORGE PC**.                                                                         |
| **Who?**   | The file was detected for the user **George**.                                                                  |
| **Why?**   | The file was downloaded from a **pirated software website** because George wanted to use the software for free. |

### 🧠 Easy Memory Trick

**5 Ws = What + When + Where + Who + Why**

---

# 📝 2. Reporting

When a harmful alert is detected, it needs to be **escalated to higher-level analysts** for timely response and resolution.

### Reporting Process

1. Harmful alert is detected.
2. The alert is **escalated**.
3. It is created as a **ticket**.
4. The ticket is assigned to the relevant person.
5. The report contains:

   * All **5 Ws**
   * Thorough analysis
   * **Screenshots as evidence** of the activity

### 🎯 Purpose

To make sure the right people get all the necessary information to investigate and resolve the alert.

---

# 🚨 3. Incident Response and Forensics

Sometimes, a detection indicates **highly malicious and critical activity**.

In such cases, **high-level teams initiate Incident Response**.

### What is Incident Response?

**Incident Response** is the process used to handle and respond to a **critical security incident**.

---

### 🔍 Forensics

Sometimes, detailed **forensic activity** is also required.

**Forensics** = Analyzing artifacts from a **system or network** to determine the **root cause of an incident**.

### 🎯 Main Goal of Forensics

> **Determine the root cause of the incident.**

# 🛡️TASK 5: Technology

**Technology** is the third pillar of SOC.

### What is Technology?

Technology refers to the **security solutions/tools** used by the SOC team to:

* Detect threats
* Respond to threats
* Reduce manual work

An organization has many **devices and applications**. Instead of checking each one separately, security solutions **centralize information** and automate detection and response.

---

## 🔐 1. SIEM

**SIEM = Security Information and Event Management**

### What is SIEM?

SIEM is a popular security tool used in SOC environments.

### Main Work:

* Collects **logs** from different network devices.
* Uses **detection rules** to identify suspicious activity.
* Correlates information from multiple log sources.
* Generates alerts when suspicious activity matches a rule.
* Modern SIEM can also use **User Behavior Analytics, Threat Intelligence and Machine Learning** to improve detection.

⚠️ **Important:**
**SIEM mainly provides Detection capabilities.**

👉 **SIEM = Collect Logs + Detect Threats**

---

## 💻 2. EDR

**EDR = Endpoint Detection and Response**

### What is EDR?

EDR monitors **endpoint devices** and gives the SOC team detailed visibility into their activities.

### Main Work:

* Provides **real-time and historical** device activity.
* Detects threats on endpoints.
* Helps investigate endpoint activities.
* Can perform **automated responses**.
* Allows analysts to respond with a few clicks.

👉 **EDR = Detect + Investigate + Respond on Endpoints**

---

## 🔥 3. Firewall

### What is Firewall?

A firewall is a **network security barrier** between internal and external networks, such as the Internet.

### Main Work:

* Monitors **incoming and outgoing traffic**.
* Filters unauthorized traffic.
* Uses detection rules.
* Identifies suspicious traffic.
* Blocks suspicious traffic before it reaches the internal network.

👉 **Firewall = Monitor + Filter + Block Network Traffic**

---

# 🧰 Other SOC Security Solutions

Other technologies used in SOC include:

* **Antivirus**
* **EPP** – Endpoint Protection Platform
* **IDS/IPS** – Intrusion Detection System / Intrusion Prevention System
* **XDR** – Extended Detection and Response
* **SOAR** – Security Orchestration, Automation and Response

The technology chosen by an organization depends on its **threat surface** and **available resources**.
